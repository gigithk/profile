Experiment E.01

Live MCP

UX Assistant

A UX review should lead to a better decision. Not another generic checklist.

Review a design once. Then use the same context to challenge it, improve it and explain the decisions.

Open live MCP ↗

A live MCP server that helps AI tools review a design, challenge its logic, suggest improvements and explain the rationale to stakeholders.

I built UX Assistant because asking a general AI model to ‘review this design’ often produces broad advice with little connection to the product problem.

The MCP gives an AI client a focused UX workflow. Start with a design input, keep the resulting review as shared context, then use that same review to challenge the idea, improve the design or prepare the case for stakeholders.

What you can do

  • Review a Figma URL, live webpage, image or HTML snippet
  • Challenge whether the solution answers the problem and requirements
  • Turn review findings into concrete design improvements
  • Create stakeholder-facing pitch points from the same review
  • Use it inside compatible AI clients through one MCP connection

01

What it does

One review, four useful next steps.

UX Assistant reviews a Figma file, live webpage, image or HTML snippet. The review becomes the starting point for challenging the design, proposing improvements or building a stakeholder-facing explanation.

Each step uses the same review run, so the designer does not have to re-explain the context for every follow-up task.

02

Why MCP

Bring the UX workflow into the AI tool you already use.

MCP lets compatible AI clients call focused tools instead of relying on one long prompt. UX Assistant can currently be connected to clients including Codex, Cursor, Claude, Windsurf and Gemini CLI.

The value is continuity: review, challenge, improve and pitch remain connected parts of one design conversation.

03

Simple workflow

Review. Challenge. Improve. Explain.

Review the design input and create a shared review run. Challenge whether the proposed solution fits the problem and requirements. Generate concrete improvements. Then translate the design decisions and constraints into clear stakeholder-facing pitch points.

  • Review - identify UX issues in the supplied design
  • Challenge - test the problem, solution and requirement logic
  • Improve - turn findings into actionable changes
  • Explain - communicate decisions in business language
04

The value

Less prompting. More design continuity.

A generic AI critique often ends as a list of suggestions. UX Assistant keeps the review usable across the decisions that follow: what to question, what to change and how to explain the change.

It is especially useful when a designer needs a second perspective quickly but still wants to own the final judgment.

05

Human role

It supports judgment. It does not replace it.

The quality of the output still depends on the context supplied: the product problem, requirements, constraints and available research. The designer remains responsible for checking the evidence and deciding what should change.
